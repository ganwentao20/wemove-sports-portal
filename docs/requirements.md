## 2. 项目目标

将现有展示型网站重构为一个可持续运营、移动端友好、可扩展的运动游戏玩具平台。系统采用单仓多应用架构，逐步提供四类入口：公共品牌官网、注册用户中心、经销商门户和运营管理后台。

本期课程验收目标：

1. 提供可运行、可构建、可测试的全栈骨架，统一 API、数据模型和权限边界。
2. 打通“访客浏览商品—用户注册登录—经销商申请—后台受控管理”的核心演示链路。
3. 用自动化测试证明认证、RBAC、企业隔离、定价优先级和错误响应等关键规则。
4. 形成需求、计划、例会、测试、操作说明、工作量证据和答辩材料的闭环。

## 4. 用户与权限

| 用户 | 能力摘要 | 数据边界 |
|---|---|---|
| 访客 | 浏览公开内容、搜索、提交联系/经销商申请 | 仅公开数据 |
| 注册客户 | 管理本人资料、收藏及订单（按实现阶段） | 仅本人数据 |
| 经销商成员 | 查看授权目录/价格、提交企业业务单据 | 仅所属 `companyId` |
| 后台员工 | 按角色权限管理业务 | 权限码 + 服务层校验 |
| 超级管理员 | 员工、角色、权限及审计管理 | 敏感操作需 MFA/审计 |

授权原则：默认拒绝、最小权限、服务端裁决。前端隐藏菜单不能代替鉴权；经销商价格不得出现在访客或零售用户响应中；员工 JWT 不能当作客户 JWT 使用，反之亦然。

## 6. 非功能需求

### 6.1 安全与隐私

1. 密码使用 bcrypt cost 12；生产 JWT 密钥至少 32 字符且不得使用开发默认值。
2. 生产启动必须显式配置 PostgreSQL、Redis、SMTP 和 HTTPS 基础地址；内部异常不得回传客户端。
3. DTO 使用白名单验证；文件上传限制 MIME、扩展名、大小及存储路径；富文本需清洗。
4. 邮箱验证/重置令牌只存 SHA-256 哈希并一次性消费；日志不得记录密码、令牌、MFA 密钥或完整环境文件。
5. 生产必须启用 HTTPS、安全 Cookie/CORS 策略、备份和最小权限数据库账户。

### 6.2 性能、可用性与兼容性

1. 关键页面目标首屏 2.5 秒内；以统一网络/设备条件记录 Lighthouse 或等价证据。
2. 目标支持 100 并发稳定访问；测试报告必须写清脚本、持续时间、P95、错误率和资源条件。
3. 支持当前主流 Chrome、Edge、Safari 及常见手机宽度；所有表格在窄屏不得撑破视口。
4. `/health/live` 仅用于进程存活探测；`/health/ready` 同时检查 PostgreSQL 与 Redis，任一依赖不可用时必须返回 HTTP 503。

### 6.3 可维护性

采用 npm workspaces、TypeScript 严格模式、ESM 后端、Prisma 迁移和 Conventional Commits。共享契约集中维护，Schema 变更须随迁移提交；PR 至少一人评审且 CI 通过后合并。

## 7. 技术架构与数据约定

浏览器访问 Next.js Web；公开数据通过 `/api/v1` 调用 NestJS API，经销商和后台受保护请求通过 Next.js 同源会话代理转发，JWT 仅保存在 HttpOnly、SameSite=Strict Cookie。API 使用 PostgreSQL 持久化、Redis 实现限流/黑名单，SMTP 在本地指向 Mailpit。API 正常响应形状为 `{ code, message, data, traceId }`，HTTP 状态码保留语义。

核心实体包括 User、Staff、Role、Permission、DealerCompany、DealerMember、Product、Variant/SKU、PriceBook、Stock、Order、UserToken 与 AuditLog。所有金额存整数分；企业业务查询必须带当前登录者解析出的 `companyId`；删除策略由数据敏感性决定，审计记录不可由业务用户删除。

## 9. 验收与追踪

每条 P0 需求至少关联一个 Issue/PR、一个责任人和一个可复核证据（自动化测试、截图、录屏或会议验收记录）。缺陷按“发现—负责人—修复提交—复测结果”闭环。最终测试报告应覆盖：正常路径、参数边界、未登录、角色越权、跨企业访问、重复令牌、限流、移动端兼容和构建部署。

课程最终交付包含：每人独立 Web 开发技术现状报告、进度计划、正式会议纪要、需求文档、测试报告、答辩 PPT、源代码和工作量占比表。会议纪要必须是结构化记录，不能用聊天截图代替；工作量比例应依据合并提交、评审、测试、文档和现场贡献在结项时确认，本文不预设比例。

## 10. 风险与后续决策

| 风险 | 影响 | 处理 |
|---|---|---|
| 需求愿景大于课程周期 | 功能半成品、答辩失真 | P0 优先，P1 纵向切片，P2 明确延期 |
| 当前站 HTTPS 不可用 | 上线安全与 SEO 风险 | 上线前修复证书、全站 301、混合内容和 sitemap |
| 分支并行修改共享 Schema | 冲突或迁移链断裂 | Schema 变更先开会，独立迁移，逐个 PR 合并 |
| Redis/SMTP 在开发环境可降级 | 测试遗漏生产依赖 | 生产启动校验强制配置；CI/测试环境启用依赖 |
| Prisma 开发工具依赖审计告警 | 供应链/稳定性风险 | 跟踪官方修复，升级前由 C/E 验证迁移与生成流程 |
