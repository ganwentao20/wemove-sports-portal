# 零售售后私有照片与说明

对应原文 USR-007、SEC-007、§16.2。迁移 `20260907341000_return_evidence` 增加 `RetailReturn.description` 和 `attachments`；订单行的售后 `items` 保存逐行说明。新增的图片功能沿用实际私有媒体扫描、签名和清理机制。

- 用户在订单明细选择退货行与数量，填写原因、附加说明、逐行问题说明并上传最多五张 JPG/PNG/WebP，每张不超过 5 MB。前后端校验数量、MIME/扩展名/字节内容、当前订单归属及已发货可退数量。
- `POST /orders/:id/return-attachments` 仅客户本人订单可用，按账户限流；上传能力绑定订单与本人，有效期 24 小时。提交退货需匹配媒体 ID、能力令牌、订单行和安全扫描状态。正式配置强制扫描时只接受 CLEAN。
- 提交后只保存媒体 ID、订单行、文件名、类型和大小，不保存能力令牌或公开 URL。通用注册用户/经销商下载接口不会暴露这些照片。
- `GET /orders/:id/returns/:returnId/attachments/:mediaId/access` 为本人签发 60 秒下载链接；后台对应 `/admin/commerce/orders/...` 需 `order:read`。原始文件无有效签名拒绝访问，扫描待处理或已删除也拒绝。
- `DELETE /orders/:id/return-attachments/:mediaId` 允许本人移除尚未提交的照片，立即禁止签名并进入持久删除队列。媒体行锁与提交校验防并发删除已经采用的附件。已提交证据作为售后商业记录留存，媒体实际引用检查阻止误删。
- 每日保留期任务将超过 24 小时且未被售后引用的上传排入私有清理队列；已提交证据不受该临时上传期限删除。个人数据导出包含本人售后说明和附件元数据，排除能力令牌。

真实回归：2026-09-08 00:11，`return-evidence.e2e-spec.ts` 3 场景与媒体生命周期 7 场景共 10/10 通过；00:12 身份/经销商/真实 Mailpit/售后图片/媒体五套件 39/39 通过。覆盖他人订单、员工客户路由、伪装图片、错误能力和订单行、清理状态拒绝、客服权限、私有下载字节与上传一致、个人导出以及移除未提交文件。

字节校验发现全局成功响应拦截器曾将 `StreamableFile` 包装为 JSON，导致媒体接口虽返回 200 但文件内容错误。本轮已透传 `StreamableFile`，用真实 PNG 上传→签名→下载逐字节比较证明修复。历史仅检查下载 HTTP 200 的测试不能替代该验证。
