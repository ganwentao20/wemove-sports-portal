# 仍需真实资源或人工完成的验收

更新：2026-09-08。本页单独列出代码补齐后不能用样例、模拟支付或本机测试代替的事项。逐项实现及自动化证据见[完整需求矩阵](final-requirements-verification-20260907.md)。这些事项不等于已正式上线；发现代码缺陷仍需修复，不能归入“缺凭据”。

| 事项 | 已实现、已验证的边界 | 尚缺内容与原因 |
| --- | --- | --- |
| 真实收款、退款、银行到账、税务票据 | 两渠道交易和售后、DEMO/HTTP 适配、签名/金额/币种/幂等/补偿、银行流水人工确认、中文 PDF；零售退款已补首次/重试的退款与付款身份、金额币种验证，不可信结果不自动入账，完整协议见[零售实施记录](../commerce/retail-completion-20260907.md) | 没有已指定商户及其正式账户、密钥和支付协议。需选定供应商后进行真实小额支付/退款和对账；若供应商协议与现有 HTTP 契约不同，需补对应适配器。该退款修复已通过 CI #49/#50 的最终整合回归，不沿用旧开发分支 CI。PDF 单据不能自动等同某司法辖区的法定发票。 |
| 正式商品、合同、税运费及品牌内容 | 可配置商品/分类/关联/评分、市场价、企业授权、税运规则、CMS 多语发布和素材工具 | 没有原站完整导出、合法素材、真实评价来源、批准合同及各市场业务口径。不能编造评价、证书、条款或翻译；正式来源到位后导入并逐项核对。库存已采用原文允许的本地数量/CSV 方案；实际 ERP/WMS 接口需供应商定义，当前未冒充已接 ERP。 |
