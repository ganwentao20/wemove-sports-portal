## 四、质量门禁与完成定义

一次交付只有同时满足以下条件才进入冻结：依赖可复现安装；Prisma 生成与迁移通过；lint、TypeScript、单元测试、数据库/HTTP/邮件集成测试通过；API 与 Web 生产构建通过；Chromium、Firefox、WebKit 回归通过；项目源码无真实 `.env`、密钥和运行时数据；课程材料中的账号、密码、统计和源码 SHA 与最终包一致。

## 五、风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 把反面“运动玩具商城”方案当成最终设计 | 以原网站为唯一前端基线，移除运行界面中的 SPORTS 定位，测试改验原站商品与内容 |
| 重复开发已有后端 | 先审计现有控制器、服务、数据库模型与回归，只有缺失能力才新增 |
| 中英文页面局部漏译 | 统一语言上下文；公共站、账号、经销商、后台分别建立浏览器回归和静态文案检查 |
| 三类登录入口造成理解偏差 | 只保留 `/login` 作为用户可见登录入口；旧路径仅兼容跳转 |
| 文档与源码版本不一致 | 完整验证后提交冻结；用独立 SHA 记录和 `git archive` 生成精确源码包 |
| 真实生产资源无法在课程环境完成 | 明确列为外部前置条件，不以模拟结果冒充正式上线 |

## 六、结项与追溯

代码冻结提交的完整 SHA、验证时间、测试统计和源码归档 SHA-256 随最终课程提交包记录。历史进度由 Git 提交记录、需求追踪矩阵和测试证据共同追溯；未发生的会议、签字或真实生产验收不补造。
