# WEMOVE SPORTS 五人大模型辅助实践说明

课程：软件开发实践 2。班级与组号：下午班第 8 组。整理日期：2026 年 9 月 8 日。

本项目五名成员在需求理解、代码开发、问题排查、测试和文档整理中使用了大模型工具。本说明汇总各成员的使用范围与复核责任。AI 实际参与了部分实现和验证，项目质量以明确的源码版本、运行记录和验收证据为依据；个人体会、团队分工和工具执行结果分别记录。

## 一 工具与职责概览

| 成员 | 职责 | 使用工具与模型记录 |
| --- | --- | --- |
| 甘文韬 | 项目统筹、架构与权限、B2B 接手及全项目整合 | Codex，OpenAI 系列大模型；依据项目任务记录 |
| 陈婧琳 | 前台品牌官网与 B2C 用户中心 | Codex；成员说明以 GPT-5.5 轻度思考模式为主 |

工具名称与底层模型是不同概念。表内版本按成员说明记录，不将 GitHub Copilot、Trae 或 Codex 的产品名称直接当作固定模型版本。

## 二 各成员的具体使用

### 甘文韬

在项目统筹和 B2B 接手阶段，甘文韬使用 Codex 阅读原始需求、已有代码与团队文档，梳理模块关系、冲突和验收缺口。辅助范围包括认证与权限、企业采购链路、官网与后台补齐、库存和支付边界、媒体与通知，以及部署和恢复工具。

本轮整合中，Codex 实际执行了代码修改、回归测试、性能分析、生产镜像验证和文档整理。甘文韬提出开发范围与交付要求，并负责组织取舍、协作和最终复核。自动化结果如实记为工具执行的证据，不将这些修改按原模块归属改写为其他成员独立完成的工作，也不把 AI 生成内容描述成全部由本人手写。

### 陈婧琳

陈婧琳主要使用 Codex 辅助理解 Next.js 前端代码、定位报错、分析组件交互和整理修改思路。具体范围包括响应式布局、首页、产品列表与详情、产品对比，以及注册登录、资料、地址和收藏等用户中心页面。

在多人协作中，大模型也用于解释 GitHub 分支同步、接口配合与冲突处理。文档方面，主要辅助调整不通顺的语句、减少重复和整理段落。个人说明强调，建议须结合现有接口和代码进行判断与修改，再通过实际运行确认；项目经历与课程体会由本人陈述。

### 周慧莹

周慧莹使用 Trae IDE 内置 AI 助手辅助生成 NestJS 模块骨架、Prisma 字段草稿与 DTO 校验模板，并用于技术报告润色、数据字典表格整理和 README 文字调整。问题排查涉及 Prisma 迁移、TypeScript 类型错误、Git 冲突及本地环境配置。

其个人说明将价格优先级、企业隔离、阶梯定价、订单事务和库存约束列为重点人工设计与审核内容。大模型提供的骨架仍需补充业务边界和测试。原说明中的介入比例属于个人自述，未提供统一统计方法，本汇总不把这些比例作为可核验工时或实际贡献比例，也不把个人阶段性说明扩大为后续整个项目均无 AI 参与。

### 倪依玲

倪依玲使用 GitHub Copilot 辅助 Admin UI 页面组件、导航布局与样式拆分，协助 CMS 富文本集成、内容持久化、媒体上传与分类、签名下载和私有资源鉴权问题排查。

其他用途包括联系工单列表与状态流转界面、SEO 配置和审计日志查看框架，以及 `docs/operation-manual.md` 的文字组织和排版。该说明对应其负责阶段的工作；后续整合版本以实际 PR 和测试记录为准，不能用“所有内容已合并 main”概括仍在草稿 PR 中的最终补齐版本。

### 龙祖怡

龙祖怡使用 ChatGPT 辅助 Node.js、Docker 和镜像环境排障，理解工程流程与 CI，并配合 E1 完成 Mailpit 和数据库集成测试的本地验证。在 E2 阶段，辅助编写目录冒烟测试、运行当时的 19 个端到端用例和 100 并发只读压测。

其说明强调区分 429 限流防护与容量数据，理解命令后再执行，如实记录环境、版本和结果。上述 19 项用例和压测属于早期个人阶段记录；最终整合测试是另一批版本证据，不能把全部新增测试及执行工作自动归为本人独立完成。

## 三 验证方法与责任

对大模型生成的代码，应核对需求、接口契约、错误处理和权限边界，再进行类型检查、构建及适当的功能测试。对测试结论，应同时保留环境、被测提交、命令、样本和运行结果；对文档，应检查姓名、任务归属、阶段及数据来源。

业务代码版本 `0d33eef` 已整合 main `5642da2` 的更新，CI #49 对 GitHub 整合检出的同一代码树验证成功：110 项单测、169 项数据库与邮件测试、67 项三引擎浏览器及性能测试，以及生产启动、扫描和恢复演练全部通过。该业务版本位于 PR #10，归档时仍为草稿、尚未合并 main。此结果是团队整合证据，不替代个人实际贡献认定或人工签收。

AI 输出可能包含过时 API、错误配置、遗漏的边界或未经验证的结论。编译成功和自动化通过只是部分证据，仍需业务复核、真实设备检查及正式环境联调。涉及密钥、账号、订单和私有文件时，必须遵守最小权限和数据保护要求。

## 四 总结

大模型帮助团队提高了理解代码、实现功能、排查问题和整理材料的效率。合理使用的前提是如实说明参与范围，保留可复核证据，并由成员和团队承担需求判断、内容真实性及交付质量责任。计划工作量、个人自述和 AI 使用比例不互相替代，最终贡献仍按实际工作记录确认。
