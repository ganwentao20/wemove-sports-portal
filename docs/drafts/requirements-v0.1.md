## 1. 引言

### 1.1 背景
WEMOVE 运动游戏玩具品牌原仅有静态展示单页，无法支撑：多语言海外 SEO、零售/批发双客群、
高频内容运营。课程实践目标是将静态页重构为**可持续自主运营的综合 Web 平台**。

### 1.2 目标与范围
- 目标：交付"品牌官网 + B2C 用户中心 + B2B 经销商门户 + 运营后台"四位一体动态系统。
- 范围（v1 课程版）：四大门户关键链路可演示、可测试、文档齐备；详见第 3 章功能清单（F-*）。
- 非目标：支付网关真实收款、多语言 i18n 上线、生产部署（以本地 Docker + CI 为交付形态）。

### 1.3 术语表
| 术语 | 含义 |
|---|---|
| SKU / 变体 | 最小可售单元（ProductVariant） |
| PLP / PDP | 商品列表页 / 商品详情页 |
| RFQ / PO | 询价报价 / 采购订单 |
| CMS | 内容管理系统（页面模块化配置） |
| RBAC / MFA | 角色权限 / 多因素认证（TOTP） |
| ISR / SSR | 增量静态再生成 / 服务端渲染（Next.js） |

## 6. 接口需求（C+组长；正式《API 规格书》由 C 输出）

- 契约：前缀 `/api/v1`；统一体 `{code,message,data,traceId}`；错误码分段（见 apps/api/src/common/errors.ts）。
- 已实装 API 一览：见 apps/api/README.md（auth 10 项、admin 12 项、catalog、health）。
- 关键时序（实现即文档）：
  1. 注册→（可选）邮箱验证→登录（限流 5 次/15min）→业务；
  2. 经销商价格链：企业专属 > 价格表 > 等级价 > B2B 默认；零售只取 MSRP/Sale（engine 单测覆盖）；
  3. 后台敏感操作：Staff 登录 → MFA x-mfa-code → 操作 → AuditLog 留痕。
- 前端接入约束：一律走 `lib/api.ts`（code!==0 抛 ApiError）。
