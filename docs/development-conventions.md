# 开发约定与注意事项（docs/development-conventions.md）

> 本文件集中存放**跨模块的工程/协作/合规注意事项**，避免污染根 README。
> 属于单个模块的细节请放入对应模块 README（`apps/web/README.md`、`apps/api/README.md`）。

## 一、API 契约约定

1. **统一响应体**：`{ code, message, data, traceId }`（code=0 成功）；
   错误码分段见 `apps/api/src/common/errors.ts`（42200 参数/40100 未登录/40300 无权限/40400 不存在/40900 冲突/42900 限流/50000 内部）。
2. 前端一律经 `apps/web/lib/api.ts` 访问（code!==0 抛 `ApiError`），**禁止散落裸 fetch**。
3. HTTP 状态保留语义；未知路由 404 已由兜底控制器归一为 JSON（勿在业务里自行拼 HTML 错误页）。

## 二、核心业务约定（容易扣分的点）

1. **价格引擎优先级（课程核心算法）**：企业专属价 → 价格表 → 经销商等级价 → B2B 默认价；
   **零售用户只取 MSRP/Sale**，永不经 dealer 价格链。实现见 `apps/api/src/pricing/pricing-engine.ts`（纯函数+单测，改前先改测试）。
2. **经销商数据边界**：一切经销商业务数据以 `companyId`（企业）为物理隔离边界，
   服务层必须注入"当前登录者所属企业"，禁止跨企业查询；游客/零售用户调用 dealer 价格接口一律 403 语义。
3. **金额存储**：一律整数"分"（`*Cents`），禁止浮点金额入库。
4. **订单/库存**：库存扣减必须在数据库事务内进行（组员 C 实现时遵守）。
5. **防越权（安全测试点）**：前端隐藏菜单不算权限控制；判定一律在服务端（守卫 + 服务层二次校验）。

## 三、认证与安全红线（组长负责基座，全员遵守）

1. C 端/经销商成员（`User`）与后台员工（`Staff`）**双体系、物理隔离**，禁止互借账号体系。
2. 密码使用 bcrypt cost=12（自适应哈希）；`JWT_ACCESS_SECRET` 生产环境必须替换为强随机值。
3. **后台敏感操作必须二次认证并留存审计日志**（`AuditService.record()`，见 apps/api/README）。
4. **登录限流与登出黑名单**已接入 Redis（单邮箱 5 次/15min、单 IP 30 次/min，见 apps/api/README）；
   Redis 不可用时自动降级并在恢复后自愈，生产环境必须常驻 Redis。
5. **邮件令牌**（邮箱验证/找回密码）一次性有效、库中只存哈希；SMTP 未配置时走"开发日志模式"，
   发送失败不阻断注册等主流程。
6. **合规红线**：产品面向儿童，但**网站账号与交易只面向成年人** ——
   注册强制 `ageConfirmed` 18+ 声明（服务端硬校验）；禁止任何面向儿童收集数据或注册账户的设计。
7. 请求入口统一挂 traceId（响应头 `x-trace-id`），审计与排障可串联。

## 四、性能与兼容硬指标

1. 关键页面首屏 ≤ 2.5s；支持 100 并发稳定访问（组员 E 出压测报告，CI 挂载待办）。
2. **严禁移动端横向溢出**：手机端=抽屉导航+单列排版；表格类组件
   （Quick Order、产品对比表等）禁止直接横向撑破屏幕，须做卡片化/纵向堆叠替代方案。

## 五、TypeScript 工程规范

1. 严格模式全开；DTO 用 class-validator 白名单校验（防参数污染）。
2. `apps/api` 为 ESM：**相对导入必须带 `.js` 后缀**（`./x.js`），容易踩坑，新文件照抄现有写法。
3. 不引入 `any`（确有需要先问组长）；函数/模块首注释标注负责人归属（M1/MA/MB/MC/MD/ME）。

## 六、Git 协作规范（6 人拉入后生效）

1. 分支：`main`（受保护，禁止直推）→ `feature/<模块>-<英文名>` → PR 合并（≥1 人评审）。
2. 提交信息用 Conventional Commits：`feat:` `fix:` `docs:` `chore:` `test:` `refactor:`。
3. 改 `apps/api/prisma/schema.prisma` 必须**同 PR 附迁移 SQL**（`npm run db:migrate` 生成）。
4. 新增依赖须在 PR 描述说明用途；CI（lint/单测/构建）绿了才能合。

## 七、数据库与本地环境注意

1. 本地数据库：`npm run db:up`（Docker PG16+Redis7）；`apps/api/.env` 由 `.env.example` 复制（不入库）。
2. 首次 clone 后按根 README「快速开始」执行；Prisma 版本固定 6.x，升级到 7 需组员 C/E 评审后统一进行。
3. 运行中的演示服务与本机 Docker 容器仅用于本地开发，**不得包含任何真实客户数据**。
